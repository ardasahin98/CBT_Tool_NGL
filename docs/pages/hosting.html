Running and hosting

The CBT Tool is a static website: HTML, JavaScript and a Python file that runs in the browser. It needs no server-side code, so any web server can host it.

Run it on your computer

Browsers do not run web workers on pages opened directly from disk (file://), so serve the folder. With Python 3 installed, from the repository folder:

python serve.py

and open http://localhost:8000. serve.py is a plain static server plus a relay to the NGL API, so loading tests from NGL works locally too. python -m http.server 8000 also works, except for the NGL connection.

Host it on a web server

Copy the repository (without .git) to any static web host: a university web server, GitHub Pages, Netlify, Cloudflare Pages or Vercel. That is all that uploading and analysing CSV files needs; loading tests from NGL needs one more step, below.

The site sets no cookies and uses no analytics. Pyodide's files are large (about 30 MB in total); the server should send .wasm files as application/wasm (most do) so the browser can compile them while they download.

Connecting to the NGL API

Browsers block a page from calling another site's API unless that site allows it (CORS). The tool tries, in order: a relay at /ngl/… on its own address, NGL directly, and the relay set in js/config.js. If all fail, the error lists what happened with each. Depending on where the tool is hosted:

  • On the NGL website itself (same origin): no relay is needed.
  • Locally: python serve.py provides the /ngl/… relay.
  • Vercel: vercel.json (at the repository root) rewrites /ngl/users/api-token and /ngl/<table>/api-index to the NGL API server-side.
  • Other static hosts (GitHub Pages, a university server): ask the NGL administrators to allow the site's origin on /users/api-token and */api-index, or deploy the Cloudflare Worker in proxy/ and set its URL as proxy in js/config.js (see proxy/README.md).

The relays forward only the token and API-index endpoints and do not log or store credentials.

GitHub Pages and this documentation

The documentation pages are HTML fragments in docs/pages/, wrapped in docs/_layout.html by tools/build_docs.py (Python standard library only). The script builds the whole published site into _site/: the tool at the root and the documentation in _site/docs/. It also checks every internal link.

python tools/build_docs.py           # build _site/
python tools/build_docs.py --serve   # build, then serve at http://localhost:8081/docs/

Pushing to main runs .github/workflows/pages.yml, which builds _site/ and publishes it to GitHub Pages. One-time setup in the repository: Settings → Pages → Build and deployment → Source: GitHub Actions.

The screenshots in docs/images/ are taken from the running tool with the examples loaded; retake them after changing the interface.

Releasing a new version

  1. Set the version in js/export.js (TOOL_VERSION), the footers of index.html and about.html, CITATION.cff and codemeta.json, and the release date in the last two.
  2. Update the cache-busting ?v= suffixes in index.html for the files that changed.
  3. Commit, tag (git tag v1.0.0) and push, then create a GitHub release from the tag.
  4. Publish the release on DesignSafe, which assigns the version its DOI, and add the DOI to CITATION.cff, codemeta.json, the README and Citation and license.
