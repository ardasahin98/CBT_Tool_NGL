Running and hosting

The CBT Tool is a static website: HTML, JavaScript and a Python file that runs in the browser. It needs no server-side code, so any web server can host it.

Run it on your computer

Browsers do not run web workers on pages opened directly from disk (file://), so serve the folder. With Python 3 installed, from the repository folder:

python serve.py

and open http://localhost:8000. serve.py is a plain static server plus a relay to the NGL API, so loading tests from NGL works locally too. python -m http.server 8000 also works, except for the NGL connection.

Host it on a web server

Copy the repository (without .git) to any static web host: a university web server, GitHub Pages, Netlify, Cloudflare Pages or Vercel. That is all that uploading and analysing CSV files needs; loading tests from NGL needs one more step, below.

The site sets no cookies and uses no analytics. Pyodide's files are large (about 30 MB in total); the server should send .wasm files as application/wasm (most do) so the browser can compile them while they download.

Connecting to the NGL API

Browsers block a page from calling another site's API unless that site allows it (CORS), and NGL does not allow other sites. The tool tries, in order: a relay at /ngl/… on its own address, NGL directly, and the relay set in js/config.js. If all fail, the error lists what happened with each. Depending on where the tool is hosted:

  • Vercel (the published tool, cbttoolngl.vercel.app): vercel.json (at the repository root) rewrites /ngl/users/api-token and /ngl/<table>/api-index to the NGL API server-side.
  • Locally: python serve.py provides the /ngl/… relay. Set NGL_URL to relay to another NGL server, e.g. a local copy of the NGL website: NGL_URL=http://localhost:8765 python serve.py.
  • Other static hosts (GitHub Pages, a university server): ask the NGL administrators to allow the site's origin on /users/api-token and */api-index, or deploy the Cloudflare Worker in proxy/ and set its URL as proxy in js/config.js (see proxy/README.md).

The relays forward only the token and API-index endpoints and do not log or store credentials.

Inside the NGL website

NGL administrators open the tool from Interpretation Tools → Cyclic Behavior Type (CBT) Tool. That NGL page shows the Vercel site in a frame, so the tool still reaches NGL through the Vercel relay, and every push that Vercel deploys shows up there too. The address is set in the NGL website's InterpretationToolsController (InterpretationTools.cbtUrl in config/app_local.php overrides it).

The NGL page passes the logged-in user's 2-hour API token to the tool, so no separate sign-in is needed:

  1. The tool, when it runs in a frame, asks the page that contains it with a cbt-ngl-request message.
  2. The NGL page gets a token for the logged-in user from /interpretation-tools/token (Admin mode only) and answers with an ngl-session message sent only to the tool's own address.
  3. The tool accepts the answer only from the page that contains it, and only if that page is on one of the addresses listed as embedOrigins in js/config.js (the NGL website and a local copy at localhost:8765).

Opened by itself, the tool asks for a normal sign-in. A local copy of the NGL website issues tokens that only it accepts, so to test this locally, serve the tool with NGL_URL=http://localhost:8765 python serve.py and set InterpretationTools.cbtUrl to http://localhost:8000/.

Publishing the tool and this documentation

The documentation pages are HTML fragments in docs/pages/, wrapped in docs/_layout.html by tools/build_docs.py (Python standard library only). The script builds the whole published site into _site/: the tool at the root and the documentation in _site/docs/. It also checks every internal link.

python tools/build_docs.py           # build _site/
python tools/build_docs.py --serve   # build, then serve at http://localhost:8081/docs/

Vercel runs the same script on every push (buildCommand in vercel.json) and publishes _site/ (outputDirectory), so the tool and this documentation are deployed together. Leave Build Command and Output Directory empty in the Vercel project settings, since they override vercel.json.

GitHub Pages (optional): pushing to main also runs .github/workflows/pages.yml, which publishes _site/ to GitHub Pages once Pages is turned on in the repository (Settings → Pages → Build and deployment → Source: GitHub Actions). GitHub Pages cannot relay to NGL, so loading from NGL does not work there.

The screenshots in docs/images/ are taken from the running tool with the examples loaded; retake them after changing the interface.

Releasing a new version

  1. Set the version in js/export.js (TOOL_VERSION), the footers of index.html and about.html, CITATION.cff and codemeta.json, and the release date in the last two.
  2. Update the cache-busting ?v= suffixes in index.html for the files that changed.
  3. Commit, tag (git tag v1.0.0) and push, then create a GitHub release from the tag.
  4. Publish the release on DesignSafe, which assigns the version its DOI, and add the DOI to CITATION.cff, codemeta.json, the README and Citation and license.
